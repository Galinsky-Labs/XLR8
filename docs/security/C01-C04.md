# Self security review: C01 bootstrap, C02 identity, C03 events, C04 registration

Date: 2026-11-15. Reviewer: the implementing assistant session (self review, **not** independent).

- **Secrets/config:** server config is separate from `/config.json`, which exposes only the engine status (tested). DB URLs are Render env vars; nothing secret is committed.
- **Sessions:** 256-bit random tokens; only SHA-256 hashes stored; `HttpOnly; SameSite=Lax; Secure` (production) cookies; expiry, logout, logout-everywhere and guest expiry enforced at authentication (tested).
- **Passwords:** scrypt (N=16384, r=8, p=1, 16-byte salt), constant work for unknown emails, 10–200 chars.
- **CSRF:** state-changing API calls require `application/json` and a matching `Origin` (or non-cross-site `Sec-Fetch-Site`); cross-origin requests get 403 (tested).
- **Authorization:** every mutation re-derives the organization role from the session; client-supplied roles/org ids are ignored; non-members get 404 for organizations/events (no existence disclosure); owner role cannot be granted via API (tested).
- **Private events:** invisible (404) unless member, registrant or invitation redeemer; excluded from listings; waitlist counts organizer-only; invitation preview reveals only title/time (tested).
- **Invitations:** 256-bit tokens, hashed at rest, expiry, revocation, max uses, email binding, idempotent replay, row lock against over-redemption (tested).
- **Capacity:** `SELECT … FOR UPDATE` on the event row serializes capacity decisions; 20 concurrent registrations for 5 seats produce exactly 5 (tested).
- **Input:** JSON body ≤ 64 KiB, length/format checks, DB CHECK constraints, parameterized SQL only.
- **Browser:** strict CSP (`script-src 'self'`, no inline), `frame-ancestors 'none'`, nosniff, no-referrer; client renders all user text via `textContent` (tested: no `innerHTML`).
- **Abuse:** in-memory per-IP limits on auth and invitation endpoints (single free instance). A shared limiter is needed before scaling out.

Residual: no email verification/account recovery (needs C22 delivery), no hosted IdP, no audit log. No blocking finding for an engine-less agenda/registration service.
